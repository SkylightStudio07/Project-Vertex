# 다이얼로그 JSON 포맷 지침

## 0. 제약사항

이 프로젝트는 `UnityEngine.JsonUtility`만 사용한다 (Newtonsoft Json.NET 패키지 없음).
`JsonUtility`는 **Dictionary를 역직렬화하지 못한다.** 그래서 분기 노드는
"id 필드를 가진 객체들의 배열"로 표현한다 (딱 분기점 찾을 때만 id로 선형 탐색).

`JsonUtility`는 다형성(폴리모피즘) 역직렬화도 지원하지 않는다. 그래서 `line`/`choice`/`end`
종류가 다른 데이터를 하나의 클래스(`DialogueLineData`)에 전부 담고, `type` 필드로 구분한다.
사용하지 않는 필드는 그냥 비워두면 된다 (JsonUtility는 없는 필드를 기본값으로 채운다).

## 1. 최상위 구조

```json
{
  "characters": [ /* DialogueCharacterData[] */ ],
  "startNode": "start",
  "nodes": [ /* DialogueNodeData[] */ ]
}
```

- `characters` — 이 대화 시퀀스에 등장하는 캐릭터 전원. 최대 4명.
- `startNode` — 재생을 시작할 노드의 `id`.
- `nodes` — 노드 배열. 분기 시 `next`로 다른 노드 `id`를 가리켜 점프한다.

## 2. characters[] — DialogueCharacterData

```json
{ "id": "koyuki", "name": "코유키", "slot": 0 }
```

| 필드 | 설명 |
|---|---|
| `id` | 코드 내부 식별자. `speaker` 필드에서 참조 |
| `name` | 화면에 표시되는 이름 |
| `slot` | 화면 배치 위치. `0`=가장 왼쪽 ~ `3`=가장 오른쪽 (최대 4명) |

> 현재 대사를 말하는 캐릭터(`speaker`와 `id`가 일치)는 원래 밝기로, 나머지는 톤 다운(어둡게) 처리한다.
> 이건 JSON이 아니라 `DialogueView`가 런타임에 비교해서 처리할 부분.

## 3. nodes[] — DialogueNodeData

```json
{
  "id": "start",
  "lines": [ /* DialogueLineData[] */ ]
}
```

`id`로 식별되는 대사 묶음 하나. 선택지의 `next`가 이 `id`를 가리켜 분기한다.

## 4. lines[] — DialogueLineData (type으로 구분)

### 4-1. type: "line" — 대사 한 줄

```json
{ "type": "line", "speaker": "koyuki", "emotion": "confident", "text": "어라? 그런데 누구시죠?" }
```

| 필드 | 설명 |
|---|---|
| `speaker` | `characters[].id` 참조 |
| `emotion` | 아래 8종 중 하나 (문자열, 대소문자 무관 권장) |
| `text` | 대사 내용 |

### 4-2. type: "choice" — 선택지 분기

```json
{
  "type": "choice",
  "options": [
    { "text": "정중하게 인사한다", "next": "polite" },
    { "text": "무시한다",         "next": "ignore" }
  ]
}
```

선택 시 해당 `next` 노드 `id`로 점프해서 재생을 이어간다.

### 4-3. type: "end" — 시퀀스 종료

```json
{ "type": "end" }
```

이 노드에서 대화가 끝남을 명시. (생략하고 lines 배열이 끝나도 종료로 처리하지만, 분기 후 합류 지점이 명확하지 않을 때 명시적으로 적어두는 걸 권장)

## 5. 캐릭터 감정 스프라이트 (emotion 값)

| 값 | 의미 |
|---|---|
| `idle` | 기본 (디폴트) |
| `laugh` | 미소/웃음 |
| `embarrassed` | 당황/곤란 |
| `blush` | 부끄러움 (홍조) |
| `annoyed` | 화남/삐짐 |
| `sad` | 슬픔/울상 |
| `confident` | 의기양양 (자신감) |
| `despise` | 경멸/정색 |

스프라이트 매핑은 `캐릭터 id + emotion` 조합으로 찾는다. (예: `koyuki_confident`)

## 6. 분기 흐름 예시

```
start ──choice──┬─(정중하게)→ polite ──end
                └─(무시)────→ ignore ──end
```

`next`로 가리킨 노드가 다시 `choice`를 가질 수도 있다 (다단계 분기).
분기끼리 같은 노드로 합류시키는 것도 가능 (`next`를 같은 id로 지정).

## 7. 현재 미구현 사항

- `DialogueScriptData.cs` / `DialogueLineData.cs` / `DialogueView.cs`는 이 포맷 이전의
  단순 버전(분기 없음, 캐릭터 1슬롯)으로 작성되어 있다. 이 지침에 맞춰 재작업 필요.
- 캐릭터 슬롯별 톤 다운 처리, 감정→스프라이트 매핑 테이블은 `DialogueView` 구현 시 추가.

# 동료 스킬 (기획)

합류한 동료마다 전투 중 쓸 수 있는 **고유 스킬**이 하나씩 생긴다. 손패와 상관없이 누르는 버튼이고, 한 번 쓰면 다시 충전될 때까지 쓸 수 없다. FGO의 마스터 스킬처럼 전투 HUD의 **지시** 버튼에서 꺼내 쓴다.

- 관련 문서: [동료_동행.md](동료_동행.md) (동행 인원·귀환 규칙), [마테리얼.md](마테리얼.md) (인연·호감도)
- 상태: **구현됨** (7절)

## 1. 한눈에 보기

| 항목 | 내용 |
|---|---|
| 개수 | 동료 1명당 스킬 1개 (동행 최대 3명 → 전투에서 최대 3개) |
| 비용 | 기본 없음 (에너지·탄약을 쓰지 않는다). 스킬별로 비용을 줄 수는 있다 |
| 충전 | **턴 충전**(N턴마다) 또는 **전투 충전**(N전투마다) 중 하나 |
| 사용 시점 | 내 턴, 카드를 낼 수 있는 때. 카드 연출 중에는 못 누른다 |
| 효과 | 카드와 같은 효과 목록(`CardEffect`)을 그대로 쓴다 |
| 대상 | 자신 / 적 하나(카드처럼 지정) / 적 전체 / 무작위 적 |
| 강화 | 최종 인연 스토리를 보고 인연 최대 레벨에 도달하면 **강화된 효과**로 바뀐다 |

## 2. 충전 규칙

| 충전 방식 | 카운트되는 때 | 충전 상태가 남는 범위 | 맞는 스킬 |
|---|---|---|---|
| **턴 충전** | 내 턴이 시작될 때 1씩 | 그 전투 안에서만. 다음 전투는 처음부터 | 자주 쓰는 작은 효과 (방어도, 드로우, 재장전) |
| **전투 충전** | 전투에서 이길 때 1씩 | 런 전체. 전투 사이에 이어진다 | 크고 드문 효과 (흡혈, 전체 공격, 큰 회복) |

- **전투 충전은 이긴 전투마다 1.** 일반·엘리트·보스 모두 같다.
- **처음 상태:** 스킬마다 `처음부터 준비됨`을 켜고 끌 수 있다.
  - 턴 충전은 꺼 두는 게 기본이다(첫 턴부터 쓰면 너무 강하다).
  - 전투 충전은 켜 두는 게 기본이다(합류한 전투에서 바로 한 번 써 볼 수 있게).
- 충전이 다 차면 그 이상은 쌓이지 않는다(1회분만 보관).
- 동료가 휴식에서 귀환하면 스킬도 같이 빠지고, 충전 상태는 버린다.
- **훈련장:** 모든 스킬이 매 훈련 전투 시작 때 준비된 상태다(연습용). 턴 충전도 첫 턴부터 쓸 수 있다.

## 3. 인연 강화

- **조건:** 그 동료의 **최종 인연 스토리**(최대 레벨 랭크업 이벤트)를 보고 **인연 최대 레벨**(`maxCoopLevel`)에 도달.
  - 호감도는 `PlayerRecord`에 저장되므로 한 번 달성하면 이후 모든 런에 적용된다.
  - 랭크업은 이벤트를 다 본 뒤에 확정되므로, 지금 구조에서는 "최대 레벨 = 최종 스토리를 봄"이다.
- **강화 방식:** 스킬 에셋에 `강화 효과 목록`을 따로 둔다. 조건을 채우면 기본 효과 대신 이것을 쓴다.
  - 수치만 오르는 게 아니라 효과가 하나 더 붙거나 충전이 줄어도 된다(`강화 충전` 칸도 따로 둔다. 비우면 기본값).
- **보이는 곳:** 지시 칸의 스킬 이름 옆에 Vertex Mark 표식이 붙고, 툴팁에 "인연 강화" 줄이 붙는다. 컷인 대사도 강화판을 쓸 수 있다.
- 강화 전 동료의 툴팁에는 "인연 Lv.MAX에서 강화: …"를 흐리게 미리 보여 준다(목표 제시).

## 4. 데이터 구조

동료 데이터(`CoopCharData`)가 스킬 에셋 하나를 가리킨다. 스킬은 별도 ScriptableObject로 둔다. 수치를 동료 데이터와 따로 조정하기 쉽게 하기 위해서다.

```
CompanionSkillData (ScriptableObject, Create → Game Asset/Companion Skill)
├ skillName          "흡혈"
├ icon               스킬 문양 (버튼 안에 들어감)
├ description        "적 하나에게서 체력을 {0.amount} 흡수합니다."   ← 카드 설명과 같은 토큰 문법
├ chargeType         Turns / Battles
├ chargeAmount       3            (3턴마다 / 3전투마다)
├ startReady         true
├ energyCost         0            (선택)
├ targeting          EffectTargetSelector (Source / PrimaryTarget / AllOpponents / RandomOpponent)
├ effects            List<CardEffect>   [SerializeReference] — 카드 인스펙터와 같은 방식으로 편집
├ enhancedEffects    List<CardEffect>   인연 강화 효과 (비우면 강화 없음)
├ enhancedCharge     0            (0이면 chargeAmount 그대로)
├ enhancedDescription
├ cutinArt           컷인 그림 (눈매 클로즈업, 5절)
└ cutinLine          컷인 대사 한 줄 (강화판 따로 가능)
```

- **효과는 카드와 같은 `CardEffect`를 쓴다.** 효과는 SO가 아니라 `[SerializeReference]` 순수 클래스라서 카드처럼 인스펙터에서 바로 편집한다. 그래서 피해, 방어도, 회복, 상태 부여, 드로우, 재장전이 새 코드 없이 바로 된다.
- **런 중 상태**(충전 진행도)는 `CooperationManager`가 동료별로 들고, 전투 안 턴 충전은 `BattleState`가 든다.

### 새로 필요한 효과

| 효과 | 내용 | 비고 |
|---|---|---|
| `LifeDrainEffect` | 피해를 주고, **실제로 들어간 피해만큼** 회복 | 방어도에 막힌 만큼은 회복하지 않는다. 피해 계산(`DamageCalculator`)의 실제 피해 값을 쓴다 |

## 5. 예시

| 동료 | 스킬 | 충전 | 대상 | 기본 효과 | 인연 강화 (안) |
|---|---|---|---|---|---|
| **치하라 쇼** | 흡혈 | 3전투마다 (처음부터 준비) | 적 하나 | `LifeDrainEffect` 6 | 흡혈 6 + `ApplyStatusEffect` 취약 1 |
| (예시) 방패형 | 엄호 | 3턴마다 | 자신 | `BlockEffect` 10 | 방어도 10, 충전 2턴 |
| (예시) 정찰형 | 표적 지정 | 4턴마다 | 적 하나 | `ApplyStatusEffect` 취약 2 + `RevealEnemyIntentsEffect` | 취약 3 |
| (예시) 보급형 | 탄약 보급 | 2턴마다 | 자신 | `ReloadAmmoEffect` + `DrawEffect` 1 | 드로우 2 |

**치하라 쇼 컷인 대사** (말수 적고 짧게 끊는 말투. 합류·인연 대사의 "쓴 만큼 채워", "우리 둘"을 이어받는다)

| 구분 | 대사 |
|---|---|
| 기본 | "…쓴 만큼, 채울게." |
| 인연 강화 | "…우리 둘 몫이야. 남김없이." |

나머지 동료는 기획안이 나오면 이 표에 채운다. 치하라 쇼를 기준으로 수치 균형을 맞춘다.
## 6. UI

색은 [아트 디렉션](../../ArtDirection/ArtDirection.md)을 따른다: **회백색(오프화이트)·먹색이 기본, 청록은 선택·준비 상태에만 제한적으로.** 빨강은 HP·경고 전용이라 스킬 UI에는 쓰지 않는다.

### 6-1. 지시 버튼 (FGO 마스터 스킬식)

동료마다 버튼을 늘어놓지 않고, 전투 HUD에 **"지시 / ORDER" 버튼 하나**를 둔다. 누르면 동행 중인 동료의 스킬 칸이 펼쳐진다.

```
  [◇ 지시  ORDER   2]        ← 접힌 상태. 오른쪽 숫자 = 지금 쓸 수 있는 스킬 수 (0이면 숨김)
   │
   ├ [얼굴] 치하라 쇼   흡혈          READY
   ├ [얼굴] 동료2       엄호          1턴
   └ [얼굴] 동료3       표적 지정     2/4
```

- **지시 버튼:** 먹색 칸 + 회백색 글자, 모서리 절단형. 쓸 수 있는 스킬이 있으면 청록 마름모가 켜지고 숫자 배지가 붙는다.
- **펼친 칸 (동료 1줄씩):** 회백색 판, 왼쪽에 얼굴 크롭(`faceFocus / faceZoom`, 마테리얼·훈련장과 같은 값), 스킬 이름, 오른쪽에 충전 표시. 동료 스탠딩과 같은 순서.
- 펼친 채로 카드를 내도 된다. 바깥을 누르거나 다시 지시 버튼을 누르면 접힌다.

| 상태 | 칸 모습 |
|---|---|
| 충전 중 | 글자·얼굴 흐림, 오른쪽에 얇은 진행 막대 + 남은 수 ("2/4" / "1턴") |
| 준비됨 | 또렷, 왼쪽 가장자리 청록 세로선, "READY" |
| 인연 강화 | 스킬 이름 옆에 Vertex Mark(4방향 별) 작은 표식, 칸 테두리 이중선 |
| 호버 | 툴팁: 스킬 이름 · 설명 · 충전 규칙 · 대사 · (강화 / 강화 미리보기) |
| 못 씀 | 적 턴, 카드 연출 중: 지시 버튼 자체가 회색 |
| 사용 직후 | 칸이 먹색으로 한 번 반전되며 접히고, 진행 막대가 0으로 |

- **위치: 왼쪽 아래.** HP 바 위 상태 아이콘 줄의 오른쪽 끝(손패 왼쪽 가장자리 앞)에 두고, 칸은 **위로** 펼친다. 펼친 칸이 플레이어·동료 스탠딩의 발 쪽을 조금 가리지만 잠깐이라 괜찮다. 정확한 좌표는 전투 HUD v3(Oratio) 목업 위에서 잡는다.
- 대상이 필요한 스킬은 칸을 누르면 카드와 같은 타게팅 화살표가 나온다. 오른쪽 클릭·ESC로 취소.

### 6-2. 컷인 (전투사관학교 구도 × VERTEX 색)

스킬을 확정하면 효과 전에 **화면 왼쪽 위**에 컷인이 짧게 지나간다.

- **구도:** 화면 왼쪽 위 모서리의 **삼각 영역** 자체가 컷인이다. 사선 경계(`/`)가 왼쪽 가장자리에서 위쪽 가장자리로 이어지고, 그 안을 동료의 **눈매 클로즈업**이 꽉 채운다. 나머지는 전투 화면 그대로.
- **동작:** 삼각 영역이 모서리에서 사선 방향으로 밀려 들어오고, 눈매가 그 안에서 반 박자 늦게 살짝 흐른다. 약 1.2초 머문 뒤 같은 방향으로 빠진다. 게임은 멈추지 않는다.
- **대사 태그:** 사선 경계선 바로 바깥에 선과 같은 각도로 먹색 태그를 붙인다. `ORDER · 흡혈 ─ "…쓴 만큼, 채울게."`
- **인연 강화:** 경계선이 청록 이중선, 삼각 안에 Vertex Mark 워터마크, 태그 위 청록 헤어라인, 강화판 대사. 새 색은 쓰지 않는다.
- 여러 동료 스킬을 연달아 쓰면 앞의 컷인이 빠진 뒤 다음 것이 들어온다(겹치지 않음).
- **필요한 아트:**
  - 동료마다: 눈매 그림 1장 (같은 크기·같은 눈 위치 규격, 삼각 마스크로 잘라 쓴다)
  - 공용: 삼각 마스크, 경계선(기본·강화), 워터마크, 대사 태그, 지시 버튼·목록 조각
  - 요청서: [LAYOUT_BRIEF.md](../../ArtDirection/CompanionSkillMockup/LAYOUT_BRIEF.md) · 구도 변경 [USER_DIRECTION_OVERRIDE.md](../../ArtDirection/CompanionSkillMockup/USER_DIRECTION_OVERRIDE.md) · 분절 [SPLIT_REQUEST.md](../../ArtDirection/CompanionSkillMockup/Split_Handoff/SPLIT_REQUEST.md)
- **지시 버튼 위치(목업 확정):** HP 바 바로 위, 왼쪽 정렬. 목록은 버튼 위로 펼친다.

## 7. 구현 순서

1. `CompanionSkillData` 에셋 + `CoopCharData.skill` 연결, `LifeDrainEffect`
2. 충전 상태: 런(전투 충전)은 `CooperationManager`, 전투(턴 충전)는 `BattleState`. 전투 승리·턴 시작에 진행. 훈련장은 항상 준비됨
3. 인연 강화 판정: 현재 호감도 레벨 = `maxCoopLevel`이면 강화 효과·충전 사용
4. 사용: `BattleManager.UseCompanionSkill(동료)` — 카드 사용과 같은 실행 경로(`EffectRunner`)로 효과 실행, 대상 지정은 카드 타게팅 재사용
5. UI: 지시 버튼 + 펼침 칸(충전 표시, 상태별 모습, 툴팁), 왼쪽 위 컷인(대사 포함)
6. 치하라 쇼 스킬 데이터, 아트 요청(LAYOUT_BRIEF)
